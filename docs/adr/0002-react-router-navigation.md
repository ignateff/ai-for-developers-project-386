# Клиентский роутинг на react-router

Приложение календаря звонков растёт до трёх и более экранов (главная, запись на звонок, предстоящие события, потом шаги сценария записи), поэтому переходы по секциям это навигация, а не подмена рендера. В каркасе страницы переключались сравнением `window.location.pathname` в `main.tsx`; при добавлении главной страницы с меню такой подход перестал совпадать с требованиями: нужны ссылки, активное состояние пункта меню и адресные страницы, на которые ведут кнопки и меню.

Решение: клиентский роутинг на react-router-dom v7 со вложенным маршрутом-лэйаутом (`<Layout>` с шапкой) в `apps/web/src/app/main.tsx`; адреса страниц на латинице (`/`, `/book`, `/events`). Альтернативы отклонены: продолжение сравнения pathname (хрупко и не масштабируется на сценарий записи) и навигация в состоянии памяти (не даёт адресуемых URL и кнопки «назад»). Следствия: набор маршрутов — часть пользовательского интерфейса, страницы должны оставаться адресуемыми, а новый экран подключается как дочерний маршрут лэйаута. Замена роутера затронет все страницы, поэтому меняем его осознанно.
