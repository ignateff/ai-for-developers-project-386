# Стек календаря звонков

Для учебного full-stack проекта используем TypeScript на клиенте и сервере в одном репозитории с pnpm workspaces. Это позволяет изучить обе части приложения, сохранив общий процесс работы с контрактом API.

Выбранный frontend-стек: React + Vite, Mantine, TanStack Query и облегчённая структура Feature-Sliced Design. Backend — Fastify; для функциональных маршрутов предусмотрены runtime-валидация входящих данных и контрактные тесты. API описываем в TypeSpec, генерируем OpenAPI, а из него — Fetch SDK с помощью Orval. OpenAPI и SDK храним в Git и проверяем актуальность генерации в CI. SDK не зависит от TanStack Query.

Для будущего хранения выбраны SQLite и Drizzle ORM с миграциями. План развёртывания — один экземпляр приложения: Fastify раздаёт API и собранный frontend в одном Docker-контейнере; файл SQLite хранится в постоянном volume. При бронировании проверка пересечений и вставка выполняются в одной транзакции SQLite `IMMEDIATE`; все пути записи броней должны соблюдать это правило. Нужны обработка `SQLITE_BUSY` и интеграционные тесты конкурентных запросов. Масштабирование на несколько хостов потребует пересмотра хранения и развёртывания.

Для тестов выбраны Vitest и Playwright. Версии инструментов, окружение и общие команды локальной разработки и CI задаём через mise; зависимости проекта фиксируем отдельным lockfile pnpm. Quality gates выбираем из применимых рекомендаций [dev-quality-gates](https://github.com/mokevnin/dev-quality-gates), не устанавливая весь каталог. Существующий workflow Хекслета сохраняем без изменений.

## Текущее состояние

Созданы каркас приложения с React, Vite и Mantine и Fastify-сервер. Клиент перешёл на клиентский роутинг (см. ADR 0002): главная страница по макету и заглушки маршрутов `/book` и `/events` подключены как дочерние маршруты общего лэйаута. Контракт пока описывает только технический health endpoint; из него генерируются OpenAPI и Orval SDK. Vitest проверяет запуск HTTP-сервера, соответствие маршрутов `/api` контракту и ответ health endpoint его OpenAPI-схеме; по выбору стека Vitest подключён к клиенту — jsdom и Testing Library покрывают главную страницу и навигацию лэйаута. Автоматический `HEAD` для `GET` отключён; явно объявленные `HEAD` сверяются с контрактом. `mise run check` локально запускает Oxlint, Oxfmt, проверку типов, тест (обе части приложения), проверку генерации, сборку и jactionlint; отдельный workflow GitHub Actions настроен на ту же команду, а Git-хуки через hk — на локальную проверку.

TanStack Query, SQLite, Drizzle, миграции, Docker-развёртывание, Playwright и runtime-валидация функциональных запросов пока не подключены. Для каждого нового endpoint и его сценариев потребуются отдельные контрактные тесты ответов. Это выбранное направление, а не описание уже работающих возможностей.

## Проверки выбора

На минимальном TypeSpec-контракте сравнили Orval 8.45.0, Hey API 0.99.0 и OpenAPI Generator 7.26.0: все три сгенерировали клиенты, прошедшие проверку компиляции и mock Fetch-сценарии с успешным ответом, конфликтом и датами. Orval выбран как TypeScript-ориентированный генератор без зависимости от Java; Hey API в этом эксперименте упал при генерации с TypeScript 7.0.2, но работал с 6.0.3. Проверка охватывала небольшой контракт и не гарантирует совместимости со всеми будущими схемами.

С Drizzle 0.45.4 и better-sqlite3 13.0.3 проверили транзакцию с `behavior: "immediate"`: в 20 запусках два процесса одновременно создавали частично пересекающиеся интервалы, и каждый раз сохранялась ровно одна запись; соседние интервалы сохранились оба. Это подтверждает работоспособность подхода в эксперименте, но не заменяет тесты приложения и проверку обработки блокировок.
