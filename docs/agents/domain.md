# Domain docs

## Before exploring

- Read the root `GLOSSARY.md` if it exists.
- Read relevant ADRs in `docs/adr/` if the directory exists.
- If either is absent, proceed silently. `/domain-modeling` creates documentation as terms and decisions are resolved.

## Layout

This is a single-context repository: `GLOSSARY.md` and `docs/adr/` live at the repo root.

## Vocabulary and decisions

Use the glossary's terms when naming domain concepts. If a needed concept is missing, reconsider the terminology or note the gap for `/domain-modeling`.

Explicitly flag any output that contradicts an existing ADR rather than silently overriding it.
