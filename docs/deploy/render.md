# Тестовый деплой на Render Free

Инструкция подготовлена по [исследованию Render MCP](../research/render-mcp-deploy.md). Успешный деплой по ней пока **не подтверждён**: при попытках через MCP и Dashboard Render запросил платёжные данные. Причина неизвестна; [Render описывает Free без карты](https://render.com/docs/free). Не добавляйте платёжный метод и не создавайте платные ресурсы без отдельного решения владельца.

## Ограничения

Это отдельная демо-копия, не production: Render Free не поддерживает постоянный диск, поэтому SQLite-данные теряются при остановке, перезапуске или деплое. Не используйте реальные бронирования. Данные Fly.io и Render не синхронизируются. Сверяйте [актуальные лимиты Free](https://render.com/docs/free) до создания сервиса.

## Подготовка

1. Проверьте, что в доступной Render опубликованной ветке есть корневой `Dockerfile`, и согласуйте репозиторий, ветку и workspace. На момент попытки это была `feat/docker-deploy`; после мержа может подойти `main`.
2. Подключите GitHub-репозиторий в Render. Проверьте существующие сервисы, чтобы не создать дубликат.
3. Если планируется MCP, настройте `https://mcp.render.com/mcp` в OpenCode. В проверенной сессии OAuth завершился ошибкой dynamic client registration, а API key работал. Для API key используйте переменную окружения процесса OpenCode, не записывайте ключ в репозиторий или чат. Подробности и ограничения доступа — в [исследовании](../research/render-mcp-deploy.md).

## Создание через Dashboard

В [Render Dashboard](https://dashboard.render.com/web/new) создайте Web Service из согласованной ветки:

| Поле                                | Значение                                                           |
| ----------------------------------- | ------------------------------------------------------------------ |
| Language / runtime                  | Docker                                                             |
| Root Directory                      | пусто, корень репозитория                                          |
| Docker Build Context                | `.`                                                                |
| Dockerfile Path                     | `Dockerfile`                                                       |
| Docker Command / Pre-Deploy Command | пусто; запуск задан в Dockerfile, миграции запускаются приложением |
| Compute                             | Free; проверьте цену перед подтверждением                          |
| Health Check Path                   | `/api/health`                                                      |
| Auto-Deploy                         | Off для изолированного теста                                       |

Выберите имя и регион; Frankfurt — возможный вариант для Европы. Переменные окружения и секретные файлы для демо не нужны: Render задаёт `PORT`, контейнер слушает `0.0.0.0`. Первый deploy запускается при создании сервиса, даже если Auto-Deploy выключен.

Через MCP создание возможно только если актуальная схема поддерживает нужные параметры и пользователь согласовал workspace и создание сервиса. Не подставляйте платный тариф при ошибке Free. Если Render требует карту, остановитесь и уточните решение владельца или обратитесь в поддержку.

## Проверка

Проверьте результат сборки и логи, затем откройте публичный URL и `/api/health`: ожидается HTTP 200 и `{"status":"ok"}`. Проверьте также прямой переход на `/admin`. Холодный старт Free после простоя может занять около минуты. Запись тестовых данных или перезапуск сервиса выполняйте только с согласия пользователя.
